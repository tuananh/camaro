# camaro-ts

A standalone, dependency-free TypeScript port of
[camaro](https://github.com/tuananh/camaro)'s XML/XPath transformation core.
Same API and template language, without the native pugixml/WASM dependency.

## Install

```sh
npm install camaro-ts
```

## Usage

```js
const { transform, toJson, prettyPrint, destroy } = require('camaro-ts');

const xml = `<HotelListResponse>
  <cacheKey>abc</cacheKey>
  <HotelSummary><hotelId>1</hotelId></HotelSummary>
  <HotelSummary><hotelId>2</hotelId></HotelSummary>
</HotelListResponse>`;

const template = {
  cache_key: '/HotelListResponse/cacheKey',
  hotels: ['//HotelSummary', { hotel_id: 'number(hotelId)' }],
};

const result = await transform(xml, template);
// { cache_key: 'abc', hotels: [{ hotel_id: 1 }, { hotel_id: 2 }] }

await destroy();
```

`transform`, `toJson` and `prettyPrint` all return promises, exactly like camaro.
`destroy()` is a no-op kept for API compatibility.

## Differences from camaro

The template language, XPath subset and output shape match camaro's own test
suite, which runs unchanged against this package. The one intentional
difference: malformed-XML detection is slightly more lenient in the streaming
fast path — some structurally invalid attributes and name characters that
pugixml rejects are accepted. Well-formed documents produce identical output.

## Layout

- `src/xml.ts` — XML parser, `toJson` conversion and pugixml-compatible printer.
- `src/xpath.ts` — XPath 1.0 tokenizer/parser/evaluator plus camaro's custom
  `title-case`, `camel-case`, `snake-case`, `upper-case`, `lower-case`,
  `string-join` and `raw` functions.
- `src/template.ts` — camaro template parsing/evaluation, including the
  simple-navigation fast paths used by the native implementation.
- `src/stream.ts` — template-aware streaming transform used for simple templates.
- `src/index.ts` — public `transform`, `toJson`, `prettyPrint`, `destroy` API.
- `dist/` — compiled CommonJS output, generated by `npm run build` (not checked in).
- `test-redirect.js` / `run-tests.js` — run the repository's original
  `../test/*.test.js` suite directly against this package.

The test suite is not copied. `run-tests.js` launches tape with a preload that
redirects the suite's `require('../')` from the original package entry point to
`dist/index.js`, so the tests always match the upstream repository.

## Development

```sh
cd ts
npm install     # also builds dist/ via the prepare script
npm test        # builds with the latest tsc, then runs the original test suite
```

Use `npm run build` to build without running the tests.
